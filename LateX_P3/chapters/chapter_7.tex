\section{Environment and Workflow}

\subsection*{C1---A Package That Downgrades Its Environment}
Installing \texttt{facenet-pytorch} on Colab broke \texttt{torchaudio}, and with it the audio encoder. The package pins an old NumPy and PyTorch, and pip quietly replaced Colab's versions, leaving \texttt{torchaudio}'s compiled extensions incompatible. Since the released EAV files already contain face crops, the package is not needed; setup installs only \texttt{transformers} and \texttt{wandb}, and if face detection is ever required the package is installed with \texttt{-{}-no-deps}.

\subsection*{C8---Case-Sensitive Folder Names}
On Colab's Linux file system, EEG files were reported missing while audio and video files loaded. One code path built the EEG folder name with different capitalisation from the folder on Drive, which Linux treats as a different name. A single mapping from modality to folder name (\texttt{Audio}, \texttt{Vision}, \texttt{EEG}) now serves every script.

\subsection*{C12---Machine-Specific Default Paths}
Scripts that worked on the first development machine failed on the second, whose Drive mount lives elsewhere, because fallback paths in \texttt{paths.py} pointed at locations that existed only on the first machine---and failed only when a file was read. Every location now comes from environment variables set per machine or per Colab session, with automatic detection of the Colab case (Section~\ref{sec:path_configuration}).

\section{Defects in the EAV Reference Code}

\subsection*{C2---A Weight-Constraint Hook That Replaced the Layer Output (Critical)}
EEGNet crashed on its first forward pass with a batch-normalisation shape error. The repository enforced EEGNet's max-norm weight constraint with forward hooks written as lambdas that call the in-place \texttt{renorm\_}. Because \texttt{renorm\_} returns the weight tensor, each lambda returned it too, and PyTorch substitutes any non-\texttt{None} hook return for the layer's output---so the depth-wise convolution's output was replaced by its own weights. The fix is a named hook function that applies the constraint and returns nothing. Anyone running the repository's PyTorch EEGNet without this fix cannot train it, which suggests that the EAV paper's EEG baseline may come from its TensorFlow implementation instead.

\subsection*{C3---Softmax Before Cross-Entropy}
\texttt{EEGNet\_tor.forward} ended with a softmax, while the trainer used \texttt{CrossEntropyLoss}, which applies its own log-softmax and expects raw scores. Feeding it probabilities flattens the gradients once any class becomes likely. The final softmax was removed. In a 50-epoch check on participant~1 this change alone improved accuracy by only about one point, so it was not the main cause of the chance-level pilot result (C5 was the likelier one).

\subsection*{C4---An Import of a Module That Does Not Exist}
\texttt{EEGNet\_tor.py} imported \texttt{Trainer\_uni} from a \texttt{Fusion} package absent from the repository, although the class is defined later in the same file. Deleting that line exposed a second dependency: \texttt{DataLoader} and \texttt{TensorDataset} had only been reachable through it. The fix removes the dead import and imports both classes from \texttt{torch.utils.data} directly.

\subsection*{C5---Training in Evaluation Mode (Critical)}
The shared trainer switched the model into training mode once, before the epoch loop, but its per-epoch validation switched it into evaluation mode. From the second epoch on, every update therefore ran with batch-normalisation statistics frozen and dropout disabled---especially harmful for a small network learning from 280 trials. The fix is one line: the training-mode switch moves inside the loop. Together with C3 and the move to the full 350-epoch budget, it took the pilot's mean EEG accuracy from 24.4\% to 50.6\%; the individual contributions were not measured separately.

\subsection*{C6---Output Size and Configuration Disagree in the ViT}
Vision training failed on its first batch with a reshape error. The EAV trainer replaced the seven-class output layer with a five-class one and set the model's \texttt{num\_labels} attribute, but not the copy held in the model's configuration, which the internal loss still read as seven. Loading the checkpoint with \texttt{from\_pretrained(num\_labels=5, ignore\_mismatched\_sizes=True)} replaces the layer and updates both values consistently.

\section{Memory and Pipeline Design}

\subsection*{C7---Preprocessing All Frames at Once}
\label{sec:c7}
The vision preprocessing step appeared to hang and then the Colab session died without an error. The trainer passed roughly 10{,}000 frames through the image processor one at a time, collected the results in a list, and then stacked them into a single $10{,}000 \times 3 \times 224 \times 224$ float tensor---about 6 GB---before moving it to the GPU; the stack exceeded the session's memory and the process was killed. Frames are now processed in batches of 64 and kept on the CPU, and the data loader moves one mini-batch at a time to the GPU. (C16 revisits this function at cross-subject scale.)

\subsection*{C9---Logits That Were Never Saved}
\label{sec:c9}
When the first 42-participant rollout finished, neither naive late fusion nor the coherence matrix could be computed: the pipeline had saved each encoder's weights, for feature extraction, but not its predictions on the test trials. A short script, \texttt{compute\_per\_modality\_logits.py}, reloaded every saved encoder and recomputed its test logits in about 20 minutes, and downstream scripts gained a setting for which logit folder to read. The cross-subject pipeline saves features and logits in one pass.

\section{Data and Interpretation}

\subsection*{C10---An Apparent Neutral Bias That Was a Small Sample}
In the three-participant pilot, EEG predicted Neutral on 40.6\% of coherence events but on only 27.8\% of all test trials, suggesting that EEGNet defaulted to Neutral when unsure and was inflating one column of the matrix. With 42 participants the two rates were 24.7\% and 25.7\%: the pilot's 32 events had simply been too few. (The larger problem with the matrix, found later, is described in Section~\ref{sec:audit_suppression}.)

\subsection*{C11---EEG and Audio-Video Come From Different Turns}
\label{sec:listenspeak_asymmetry}
Checking how trials correspond across modalities showed that EAV's EEG comes from the participant's listening turns and its audio and video from their speaking turns. Each ``trial'' therefore pairs the neural response to a cue with the behavioural response to it, not a single moment. Correcting this would need the raw recordings and a new preprocessing pipeline, so it is treated as a property of the data: it barely affects classification, but it limits what trial-level agreement between EEG and audio-video can mean (Section~\ref{sec:audit_alignment}).

\section{Scope}

\subsection*{C13---A Research Framing That Could Not Be Delivered}
The original goal, continuous emotion tracking on arbitrary video, proved infeasible halfway through: EEG needs electrodes on the scalp, so on films or online video the system would in effect be audio-visual only, not the trimodal system the thesis was about. The work was refocused on the EAV corpus, first on cross-modal coherence and, after the final-phase audit showed the coherence patterns to be indistinguishable from EEG classification error (Section~\ref{sec:audit_suppression}), on subject calibration and few-shot adaptation. The code and results produced before each change were kept and reused.

\section{Cross-Subject Evaluation Challenges}
\label{sec:cs_challenges}

The cross-subject evaluation of Chapter~\ref{chap:crosssubject} introduced a further
five challenges. Three are engineering defects that arose specifically from scaling a
per-subject pipeline to fold scale; two are methodological.

\subsection*{C14---Encoder-Cache Leakage (Critical, Methodological)}

\textbf{Symptom:} None. This is a defect that produces no error and no visibly
anomalous number, which is what makes it dangerous.

\textbf{Root cause:} The obvious implementation of a cross-subject evaluation reuses
the cached per-subject encoders and features from the within-subject rollout, training
a fusion head on 41 participants' cached features and testing on the 42nd. But each
cached encoder was fine-tuned on its own participant, so the held-out participant's
features are produced by a model already fitted to that participant. The resulting
accuracy would be inflated and would fall plausibly between the true within-subject
and cross-subject values, giving no signal that anything was wrong.

\textbf{Resolution:} All three encoders are retrained from scratch per fold on
training participants only. The constraint is documented directly in the pipeline's
module docstring, because it is the kind of shortcut a future contributor would
reasonably attempt. This retraining constitutes essentially the entire computational
cost of the cross-subject evaluation.

\subsection*{C15---Clip/Frame Shape Mismatch at Fold Scale}

\textbf{Symptom:} \texttt{ValueError: Could not make a flat list of images}, raised by
the Hugging Face image processor during fold-wise vision training.

\textbf{Root cause:} \texttt{ImageClassifierTrainer} flattens clips into frames
internally and derives its frames-per-clip count from the second dimension of the
training array. The fold-scale data loader pre-flattened clips into frames before
passing them in, so the trainer iterated over the rows of individual frames and
handed the processor two-dimensional arrays of pixel values.

A second defect was latent behind the first: the fitting and inner-validation sets
were sampled independently and could receive different frames-per-clip counts. Since
the frames-per-clip value is read from the fitting array alone and applied to both,
the validation labels would have desynchronised from the validation frames.

\textbf{Resolution:} The loader preserves clip structure and per-clip labels, and a
single sampling plan is computed per fold and applied to both splits. A regression
test replays the trainer's own flattening and label-repetition logic against the
pooled array, so this class of shape error fails on CPU in seconds rather than after a
fold's worth of GPU time.

\subsection*{C16---Budgeting the Preprocessed Tensor, Not the Raw Frames}

\textbf{Symptom:} The process was terminated immediately after the final
preprocessing batch, with no exception.

\textbf{Root cause:} Two compounding errors. First, the RAM guard budgeted the raw
uint8 frames (9.4 KB each), but \texttt{preprocess\_images} resizes every frame to
$224 \times 224$ float32---602 KB per frame, 64 times larger. A budget believed to be
0.5 GB was in reality approximately 36 GB. Second, the method assembled its output by
appending each batch to a list and calling \texttt{torch.cat}, which holds the list
and its concatenated copy simultaneously, doubling peak memory at the very last batch.

This is the same function in which the within-subject RAM exhaustion of
Section~\ref{sec:c7} occurred, and the earlier fix---introducing the
\texttt{torch.cat}---is what created the second half of the new failure.

\textbf{Resolution:} The budget is applied to the preprocessed size and is
configurable at the command line; the output is written into a preallocated tensor
rather than concatenated, keeping peak memory equal to the size of the result. The
general lesson is that a fix which scales a pipeline up by an order of magnitude
warrants re-examining the fix itself, not merely the code around it.

\subsection*{C17---Trainers Persist the Final Epoch, Not the Best}

\textbf{Symptom:} EEG inner-validation accuracy was higher at 60 epochs (0.3833) than
at 200 (0.3567), while training loss continued to fall.

\textbf{Root cause:} Both \texttt{Trainer\_uni} and \texttt{ImageClassifierTrainer}
compute validation accuracy every epoch but neither returns it nor retains the
corresponding weights; the driver saves whatever state the final epoch leaves behind.
At fold scale EEGNet overfits well before the epoch budget, so the persisted model was
systematically worse than the best model observed during the same run.

A related failure appeared once selection was added for vision: the selector initially
ranged over both the frozen and fine-tuning phases and chose a frozen-backbone
checkpoint whose inner-validation accuracy exceeded the fine-tuned one by 0.25
percentage points---inside the approximately 0.8-point noise floor of a 3,600-frame
validation set---while scoring 10 points worse on held-out participants.

\textbf{Resolution:} Epoch budgets become upper bounds and the best
inner-validation checkpoint is retained, with early stopping for EEGNet. Vision
selection is restricted to the fine-tuning phase, on the principle that a
frozen-backbone model is a linear probe rather than an earlier epoch of the
architecture under evaluation. The broader lesson is that model selection requires a
validation set sized to the decision being made, not merely to the metric: a criterion
finer-grained than its own noise floor will choose arbitrarily, and the consequences
need not be small.

\subsection*{C18---Stale Code in the Remote Runtime}

\textbf{Symptom:} A crash reproduced byte-for-byte after the fix had been written,
tested and committed---including a log line that no longer existed in the fixed code.

\textbf{Root cause:} The workflow authors code locally and executes it in a Colab
runtime that pulls from GitHub. A fix that is committed but not pushed, or pushed but
not pulled, reproduces the original failure exactly. This occurred three times and
cost several hours of GPU time.

\textbf{Resolution:} The pipeline prints its own short git commit hash and a
working-tree-dirty flag before performing any work, so verifying that the running code
is the intended code is a one-line check rather than an inference from log formats.

\section{Final-Phase Integrity Challenges}
\label{sec:p3_challenges}

The final phase of the thesis re-examined the Pre-Thesis~II results before building on
them. Six further challenges arose. Four are methodological and concern whether a
reported number means what it appears to mean; two are analysis bugs caught before
their output was used.

\subsection*{C19---Epoch Selection on the Test Set (Critical, Methodological)}

\textbf{Symptom:} None at the time. The learned fusion heads beat naive late fusion by
2.7--7.2 points within-subject, a plausible result that nothing contradicted until the
cross-subject evaluation reversed it.

\textbf{Root cause:} The three Pre-Thesis~II fusion scripts evaluated each head on the
test trials after every epoch and reported the best, so each reported accuracy was the
maximum of 80 test measurements. Naive late fusion has no epochs and received no such
boost. The practice was described openly in the report as ``best-test-epoch
checkpointing''; the error was in not recognising it as selection on the test set.

\textbf{Resolution:} \texttt{p2\_leakfree.py} re-ran the exact recipe with three leak-free
readouts and one test-selected readout from the same trajectories, measuring the
inflation directly at 5.3--7.5 points (Section~\ref{sec:audit_selection}). All fusion
figures in this report are leak-free, the state-of-the-art claim is withdrawn, and the
cross-subject pipeline selects epochs on inner-validation participants only. The
lesson: a selection rule must be written down together with the data it is allowed to
see, and ``best epoch'' is incomplete until it says best on what.

\subsection*{C20---The Report Described a Different Dropout Scheme}

\textbf{Symptom:} The Pre-Thesis~II methodology chapter stated that softhard modality
dropout expands each batch of $N$ trials into four sub-batches ($4N$ trials), one per
modality configuration.

\textbf{Root cause:} The implementation in \texttt{day7\_modality\_dropout.py} does
something different: for each sample independently, with probability 0.5, it zeroes
one randomly chosen modality and rescales the remaining ones by $3/n_{\mathrm{active}}$.
The text described the design as first planned; the code implemented the scheme of
the reference repository \cite{Chumachenko2022SelfAttention}. Every reported number
came from the code.

\textbf{Resolution:} Section~\ref{sec:modality_dropout} now describes the implemented
scheme. Methodology text is checked against the function it describes, not against the
plan.

\subsection*{C21---A Below-Chance Identity Probe}

\textbf{Symptom:} After per-participant normalisation, the 42-way identity probe scored
0.0\%, far \emph{below} the 2.4\% chance rate.

\textbf{Root cause:} The normalisation statistics were computed from all of a
participant's trials, but the probe was trained on one half and tested on the other.
Subtracting the full-set mean makes the two halves' means mirror images of each other,
so the probe learned a direction that is systematically wrong on the held-out half.
Below-chance accuracy is as much a sign of leakage as above-chance accuracy.

\textbf{Resolution:} The statistics are computed from the probe's training half only,
which places the probe at chance (2.4--2.5\%). The unfixed version would have overstated
how much identity calibration removes.

\subsection*{C22---A Mislabelled Logits Key}

\textbf{Symptom:} None; the saved file had the expected keys and shapes.

\textbf{Root cause:} Stage C of the cross-subject pipeline wrote the logits of the
modality-dropout head under the key \texttt{cross\_attn}, so any consumer reading that
key silently received a different model.

\textbf{Resolution:} Caught in review before folds 1--4 were run; each head now writes
under its own name, and the trained heads themselves are saved so downstream analyses
run the exact models that were scored rather than re-training them.

\subsection*{C23---Double-Counted Confidence}

\textbf{Symptom:} Every confidence-weighted dynamic late-fusion variant scored below
plain averaging on unseen participants, by up to 3.8 points
(Section~\ref{sec:cal_negative}).

\textbf{Root cause:} The premise was flawed. Mean-softmax averaging is already
confidence-weighted, because a confident modality contributes a peaked distribution that
dominates the mean; explicitly weighting by confidence again counts it twice and gives
over-confident modalities more control. The encoders are over-confident on unseen
participants (fitted temperatures 1.5--2.0).

\textbf{Resolution:} Recorded as a negative result, with the calibration diagnostic and
temperature-scaling control that explain it. The failure redirected the work from
reweighting decisions to normalising the input representation, which is where the
thesis's main result was found.

\subsection*{C24---An Alignment Check That Could Not Fail}

\textbf{Symptom:} All 84 train and test splits had identical label sequences across the
three modalities---an apparently strong confirmation of trial alignment.

\textbf{Root cause:} Every sequence was sorted into five class blocks. Any two
class-blocked sequences with equal class counts match element-wise, so the check was
guaranteed to pass whatever the underlying trial order.

\textbf{Resolution:} \texttt{label\_sequence\_check.py} reports the number of label
changes along each sequence and declares a match uninformative when the sequence is
blocked. Trial correspondence is reported as unverified
(Section~\ref{sec:audit_alignment}). The general lesson for every check in this
chapter: before trusting a test that passes, confirm that it was capable of failing.
